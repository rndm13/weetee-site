# Реєстр модулів — Портал документації ПЗ

| Модуль | Призначення | Володіє | Не володіє | Ключові залежності | Статус документа |
|---|---|---|---|---|---|
| Authentication / Авторизація | Облікові записи, вхід і керування сесією | Дані облікового запису, стан доступу, перевірка облікових даних | Темами, дописами, адміністративними діями | Laravel Auth, PostgreSQL, HTTP middleware | Draft; звірити з реалізацією |
| Forum / Форум | Дискусії щодо ПЗ | Категоріями (якщо вони є), темами, дописами та їх станом | Паролями, призначенням системних ролей | Authentication, перевірки доступу, PostgreSQL | Draft; звірити з реалізацією |
| Administration / Адміністрування | Привілейоване керування сайтом | Адміністративними сценаріями, ролями/правами, модераційними діями як оркестрацією | Первинними правилами зберігання дописів/тем | Authentication, Forum, Laravel Policies/Gates | Draft; звірити з реалізацією |
| Documentation / Опис і документація ПЗ | Відображення опису продукту та документації | Публічним інформаційним контентом, якщо він моделюється як окремий тип даних | Автентифікацією та форумними обговореннями | Laravel routing/views, Vite | Не описано окремо в цьому комплекті |

## Правила меж модулів

- `Authentication` підтверджує ідентичність користувача; рішення про те, чи дозволена конкретна дія з темою/дописом, приймається політикою відповідного ресурсу.
- `Forum` зберігає авторство через стабільний ідентифікатор користувача, але не копіює пароль, email-відновлення чи інші облікові секрети у форумні записи.
- `Administration` може ініціювати блокування облікового запису або модерацію контенту, проте кожна зміна виконується через відповідальну операцію модуля-власника даних.
- Назви `User`, `Topic`, `Post`, `Role` тощо в бізнес-документах — логічні концепти. Перед використанням як точних імен PHP-класів або таблиць їх потрібно звірити з репозиторієм.
